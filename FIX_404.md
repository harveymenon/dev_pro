# 🔧 Fix 404 Error on GitHub Pages

Your site is returning a 404 error. Let's troubleshoot and fix this step by step.

## 🔍 Step 1: Verify Deployment Status

### Check GitHub Actions
1. Go to: `https://github.com/harveymenon/dev_pro/actions`
2. Look for the **"Deploy to GitHub Pages"** workflow
3. Check if it completed successfully (green checkmark ✅)

**If it's still running:**
- Wait for it to complete (usually takes 1-2 minutes)
- Refresh the page after it finishes

**If it failed:**
- Click on the failed workflow
- Check the error logs
- Common issues:
  - Build errors (check the build step)
  - Permission errors (check workflow permissions)
  - Missing dependencies

## 🔧 Step 2: Configure GitHub Pages Settings

### Verify Pages Configuration
1. Go to: `https://github.com/harveymenon/dev_pro/settings/pages`
2. Under **"Build and deployment"**, verify:
   - **Source**: Should be **"GitHub Actions"** (not "Deploy from a branch")
   - If it says "Deploy from a branch", change it to "GitHub Actions"

### If You See "Deploy from a branch"
This means GitHub Pages is looking for a `gh-pages` branch, but your workflow uses the modern deployment method.

**Fix:**
1. Change **Source** to **"GitHub Actions"**
2. Save the settings
3. Wait 1-2 minutes
4. Refresh your site

## 🚀 Step 3: Manually Trigger Deployment

If the automatic deployment didn't work, trigger it manually:

1. Go to: `https://github.com/harveymenon/dev_pro/actions/workflows/deploy-pages.yml`
2. Click **"Run workflow"** button (right side)
3. Select branch: **main**
4. Click **"Run workflow"**
5. Wait for it to complete

## 🧹 Step 4: Clear Cache and Hard Refresh

### Browser Cache
- **Windows/Linux**: `Ctrl + Shift + R`
- **Mac**: `Cmd + Shift + R`
- Or open in incognito/private window

### GitHub Pages Cache
GitHub Pages can take 1-10 minutes to fully deploy. Try:
1. Wait 5 minutes
2. Clear browser cache
3. Try again

## ✅ Step 5: Verify the URL

### Correct URL Format
```
https://harveymenon.github.io/dev_pro/
```

**Important:**
- Must end with `/` (trailing slash)
- Repository name must match exactly: `dev_pro`
- Username must be correct: `harveymenon`

### Try These URLs
1. With trailing slash: `https://harveymenon.github.io/dev_pro/`
2. Without trailing slash: `https://harveymenon.github.io/dev_pro`
3. With index.html: `https://harveymenon.github.io/dev_pro/index.html`

## 🔬 Step 6: Check Build Output

### Verify Build is Correct
Run this locally to ensure the build works:

```bash
npm run build
```

Check the `dist/` folder:
```bash
ls -la dist/
```

You should see:
```
dist/
├── index.html
└── assets/
    ├── index-*.css
    └── index-*.js
```

### Check index.html Content
Open `dist/index.html` and verify it has the correct base path:

```html
<script type="module" crossorigin src="/dev_pro/assets/index-*.js"></script>
<link rel="stylesheet" href="/dev_pro/assets/index-*.css">
```

If it shows `/assets/` instead of `/dev_pro/assets/`, the base path is wrong.

## 🛠️ Step 7: Fix Base Path (If Needed)

### Check vite.config.js
```javascript
export default defineConfig({
  base: '/dev_pro/',  // Must match your repository name
  // ...
});
```

### If Base Path is Wrong
1. Update `vite.config.js`:
   ```javascript
   base: '/dev_pro/',
   ```

2. Rebuild:
   ```bash
   npm run build
   ```

3. Commit and push:
   ```bash
   git add vite.config.js
   git commit -m "fix: Correct base path for GitHub Pages"
   git push origin main
   ```

4. Wait for deployment to complete
